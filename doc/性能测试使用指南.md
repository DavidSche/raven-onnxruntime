## 概述

性能测试工具位于 `examples/` 目录，由以下文件组成：

**性能测试**

| 文件 | 职责 |
|------|------|
| `bench_engine.go` | 统一引擎接口 `BenchEngine`、所有模型适配器、工厂函数、统计计算（含 StdDev/CV） |
| `bench_runner.go` | 运行器：单图/目录/批量/视频帧/视频流/批量扫描/精度验证 |
| `bench_report.go` | 报告格式化：表格输出（含 StdDev/CV 列）、CSV 导出 |
| `bench_test.go` | 测试入口：20+ 个预定义测试函数 |

**准确性测试**

| 文件 | 职责 |
|------|------|
| `accuracy_coco.go` | COCO 数据集解析、IoU 计算、mAP 计算（COCO 风格 11 点插值） |
| `accuracy_engine.go` | 准确性评估引擎接口、各模型适配器、评估运行器、对比报告 |
| `accuracy_test.go` | 准确性测试入口：10+ 个预定义测试函数 |

核心设计采用 **适配器模式**，将所有模型引擎统一为 `BenchEngine` 接口：

```go
type BenchEngine interface {
    Name() string
    Task() string
    Predict(img image.Image) (int, error)
    PredictBatch(imgs []image.Image) (int, error)
    SupportsBatch() bool
    Destroy()
}
```

## 快速开始

### 前置条件

1. 准备 ONNX 模型文件，放置在仓库根目录 `models/`
2. 准备 ONNX Runtime 动态库（如 `lib/onnxruntime.dll`，也可通过 `RAVEN_ORT_LIB_PATH` 覆盖）
3. 准备测试图片（如 `test.png`、`person.jpg`）

### 运行检测模型对比

```bash
cd examples
go test -run TestBenchDetModels -v -timeout 30m
```

### 使用 CUDA 加速

所有测试均支持通过 `RAVEN_USE_CUDA` 环境变量统一控制 CUDA 启用：

```bash
# 方式 1：通过环境变量（推荐，适用于所有测试）
set RAVEN_USE_CUDA=1
go test -run TestBenchDetModels -v -timeout 30m

# 方式 2：使用专门的 CUDA 测试函数
go test -run TestBenchDetModelsCuda -v -timeout 30m
```

### 运行视频对比测试

```bash
# 使用环境变量指定视频路径
set VIDEO_PATH=C:\Videos\test.mp4
go test -run TestBenchDetVideo -v -timeout 30m

# 或将视频文件放在 examples/ 目录下自动检测
```

## 准确性测试

准确性测试使用 **COCO 2017 val** 数据集，通过计算 mAP（mean Average Precision）指标评估模型的检测/分割准确性。

### 数据集准备

使用 `scripts/prepare_coco.py` 脚本自动下载和准备 COCO 数据集：

```bash
# 下载 100 张图片的子集（默认，约 15MB）
python scripts/prepare_coco.py

# 下载 500 张图片
python scripts/prepare_coco.py --num-images 500

# 下载完整 val2017 数据集（5000 张图片，约 1GB）
python scripts/prepare_coco.py --full

# 自定义输出目录
python scripts/prepare_coco.py --output-dir /path/to/models
```

脚本会自动：
1. 下载 COCO 2017 标注文件（`instances_val2017.json`）
2. 下载指定数量的 val2017 图片
3. 生成子集标注文件（`instances_val2017_subset.json`）

数据集目录结构：

```
models/coco/
├── val2017/
│   ├── 000000000139.jpg
│   ├── 000000000285.jpg
│   └── ...
└── annotations/
    ├── instances_val2017.json          # 完整标注
    └── instances_val2017_subset.json   # 子集标注
```

**环境变量配置**：

| 变量 | 含义 | 默认值 |
|------|------|--------|
| `RAVEN_COCO_DIR` | COCO 图片目录 | `models/coco/val2017` |
| `RAVEN_COCO_ANN` | COCO 标注文件路径 | `models/coco/annotations/instances_val2017.json` |
| `RAVEN_ACC_MAX_IMAGES` | 最大评估图片数（0=全部） | `100` |

### mAP 指标说明

| 指标 | 含义 |
|------|------|
| mAP @0.50:0.95 | COCO 标准 mAP，IoU 阈值从 0.50 到 0.95（步长 0.05）的平均 AP |
| mAP @0.50 | IoU=0.50 时的 AP，即 PASCAL VOC 标准 mAP |
| mAP @0.75 | IoU=0.75 时的 AP，更严格的定位要求 |
| Per-class AP | 每个类别的 AP@0.50，用于分析模型在不同类别上的表现 |

**关键说明**：
- 准确性测试使用低置信度阈值（0.001），确保所有候选框都被评估
- mAP 计算采用 PASCAL VOC 风格的 11 点插值法
- COCO 类别 ID 与 YOLO 类别 ID 的映射已内置
- 评估结果与官方 COCO 评估可能存在微小差异（插值方法不同）

## 配置参数

### BenchConfig

```go
type BenchConfig struct {
    WarmupRuns int    // 预热迭代次数（默认 3）
    BenchRuns  int    // 基准迭代次数（默认 30）
    UseCuda    bool   // 是否使用 CUDA
    LibPath    string // ONNX Runtime 库路径
}
```

### EngineSpec

通过 `EngineSpec` 指定要测试的模型：

```go
type EngineSpec struct {
    Name      string // 模型名称: "yolo26" / "yolov11" / "rfdetr" / "ltdetr" / "edgecrafter"
    Task      string // 任务类型: "det" / "seg" / "pose" / "obb" / "cls"
    ModelPath string // ONNX 模型文件路径
    LibPath   string // ONNX Runtime 库路径
    UseCuda   bool   // 是否启用 CUDA
    DynBatch  bool   // 是否启用动态 batch（仅支持此字段的模型生效）
}
```

func TestBenchCustom(t *testing.T) {

## 结果解读

### 统计指标说明

| 指标 | 含义 |
|------|------|
| Avg(ms) | 平均推理延迟 |
| P50(ms) | 中位数延迟（50% 的推理在此时间内完成） |
| P95(ms) | 95 百分位延迟（95% 的推理在此时间内完成） |
| P99(ms) | 99 百分位延迟（99% 的推理在此时间内完成） |
| Min(ms) | 最小推理延迟 |
| Max(ms) | 最大推理延迟 |
| FPS | 每秒处理帧数（1 / Avg） |
| Errors | 推理过程中的错误次数 |
| StdDev(ms) | 延迟标准差，衡量波动幅度 |
| CV% | 变异系数（StdDev / Avg × 100%），衡量稳定性。CV% > 15% 表示结果不稳定 |
| PeakMemoryMB | 峰值 Go 运行时内存占用（MB） |

### 如何分析

1. **关注 P50 而非 Avg**：P50 更能反映典型性能，Avg 容易被极端值拉偏
2. **关注 P95/P99**：衡量尾延迟，对实时应用至关重要
3. **关注 CV%**：变异系数 > 15% 说明结果不稳定，需要增加迭代次数或排查干扰因素
4. **对比加速比**：报告末尾自动计算相对第一个模型的加速比
5. **批量吞吐量**：批量测试中 `throughput = batch_size × FPS`，反映实际处理能力
6. **规模选型**：同模型不同规模对比中，选择满足延迟要求的最小规模以节省资源

### 典型性能参考

不同硬件环境下的性能差异较大，以下为一般性参考：

| 场景 | CPU (ms/img) | CUDA (ms/img) | 说明 |
|------|-------------|---------------|------|
| 轻量检测 (EdgeCrafter-s) | 8-15 | 2-5 | 边缘部署首选 |
| 通用检测 (YOLO26s) | 10-20 | 3-6 | 精度与速度平衡 |
| Transformer 检测 (RF-DETR/LTDETR) | 15-30 | 5-10 | 更高精度 |
| 分割任务 | 15-35 | 5-12 | 比检测多 50-80% |
| 姿态估计 | 12-25 | 4-8 | 与检测相近 |

> 以上数据仅供参考，实际性能取决于模型大小、输入分辨率、硬件配置等因素。

## 扩展新模型

当添加新模型时，按以下步骤扩展性能测试：

### 1. 实现适配器

在 `bench_engine.go` 中添加：

```go
type newModelDetAdapter struct {
    engine *newmodel.DetEngine
    name   string
}

func (a *newModelDetAdapter) Name() string         { return a.name }
func (a *newModelDetAdapter) Task() string         { return "det" }
func (a *newModelDetAdapter) SupportsBatch() bool  { return true }
func (a *newModelDetAdapter) Destroy()             { a.engine.Destroy() }
func (a *newModelDetAdapter) Predict(img image.Image) (int, error) {
    res, err := a.engine.Predict(img)
    if err != nil { return 0, err }
    return len(res), nil
}
func (a *newModelDetAdapter) PredictBatch(imgs []image.Image) (int, error) {
    res, err := a.engine.PredictBatch(imgs)
    if err != nil { return 0, err }
    total := 0
    for _, r := range res { total += len(r) }
    return total, nil
}
```

### 2. 添加工厂函数

在 `CreateEngine` 的 switch 中添加 case：

```go
case "newmodel":
    return createNewModelEngine(spec)
```

### 3. 添加测试

在 `bench_test.go` 中将新模型加入 `specs` 列表即可。

## 常见问题

### Q: 测试结果不稳定怎么办？

A: 增大 `BenchRuns`（如 50 或 100），并确保测试期间没有其他高负载进程。首次推理通常较慢，`WarmupRuns` 会处理这个问题。查看 CV% 列，如果 > 15% 说明结果不稳定。

### Q: 如何统一启用 CUDA？

A: 设置环境变量 `RAVEN_USE_CUDA=1`（或 `true`），所有测试函数都会自动启用 CUDA，无需运行专门的 Cuda 后缀测试函数。

### Q: 如何验证推理结果是否正确？

A: 使用 `ValidateEngine` 函数验证检测数量是否在预期范围内：

```go
err := ValidateEngine(engine, img, 1, 50)  // 期望检测数量在 1~50 之间
if err != nil {
    t.Fatalf("validation failed: %v", err)
}
```

### Q: 如何测试不同输入分辨率？

A: 在 `EngineSpec` 中对应的 Config 中设置 `InputSize`，或在自定义测试中修改 Config。

### Q: 视频测试报错 "ffmpeg not found"？

A: 安装 ffmpeg 并确保其在系统 PATH 中：
- Windows: 从 https://ffmpeg.org/download.html 下载并添加到 PATH
- Linux: `sudo apt install ffmpeg`
- macOS: `brew install ffmpeg`

### Q: CUDA 测试比 CPU 还慢？

A: 首次 CUDA 推理需要初始化，增大 `WarmupRuns`（如 5-10）。对于小模型，CPU 可能更快（GPU 传输开销占比高）。

### Q: 如何只运行特定模型的测试？

A: 使用 `-run` 参数匹配测试函数名：
```bash
go test -run TestBenchYOLO26VsLTDETR -v
```

### Q: 模型文件路径如何配置？

A: 推荐使用 `ExampleModelPath` 函数统一解析路径，它会自动拼接 `models/` 根目录与子目录和文件名：

```go
ModelPath: ExampleModelPath("yolo26", "yolo26s.onnx")  // → models/yolo26/yolo26s.onnx
ModelPath: ExampleModelPath("ecdet", "ecdet_s.onnx")   // → models/ecdet/ecdet_s.onnx
```

默认模型根目录为仓库根目录下的 `models/`，可通过 `RAVEN_MODELS_DIR` 环境变量统一覆盖。ONNX Runtime 库路径同理，使用 `ExampleORTLibraryPath()` 自动解析。
