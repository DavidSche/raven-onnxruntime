raven-onnxruntime User Manual

A Zero-CGO ONNX Runtime Go inference framework based on purego, providing ready-to-use wrappers for YOLO26 / YOLOv11 / SAM2 / SAM3 / RF-DETR models

Go 1.24+Zero-CGOCUDA SupportBatch Inference

Project Overview

raven-onnxruntime is a Go inference library built on ONNX Runtime, using purego to achieve Zero-CGO calls to the ONNX Runtime shared library, and providing ready-to-use wrappers for the YOLO model family and SAM2/SAM3.

This project is a merged version of go-vision and onnxruntime_purego, with significant improvements in performance and stability.

Quick Start

Prerequisites

  • Go 1.24+
  • ONNX Runtime shared library (onnxruntime.dll / libonnxruntime.so / libonnxruntime.dylib)
  • (Optional) NVIDIA GPU + CUDA for GPU acceleration

Installation

go get github.com/DavidSche/raven-onnxruntime

Minimal Example: YOLO26 Object Detection

package main

import (
    "fmt"
    "github.com/DavidSche/raven-onnxruntime/vision/yolo26"
    "github.com/up-zero/gotool/imageutil"
)

func main() {
    cfg := yolo26.DefaultDetConfig()
    cfg.ModelPath = "models/yolo26m.onnx"
    cfg.OnnxRuntimeLibPath = "./lib/onnxruntime.dll"
    cfg.UseCuda = true

    engine, err := yolo26.NewDetEngine(cfg)
    if err != nil { panic(err) }
    defer engine.Destroy()

    img, _ := imageutil.Open("test.jpg")
    results, err := engine.Predict(img)
    if err != nil { panic(err) }

    for _, res := range results {
        fmt.Printf("ClassID: %d, Score: %.2f, Box: %v\n",
            res.ClassID, res.Score, res.Box)
    }
}
Tip

All engines follow the same pattern: Create Config → Create Engine → Call Predict → Process Results → Destroy to release resources. Simply swap the engine type and config to switch between different models.

Overall Architecture

raven-onnxruntime adopts a two-layer architecture design:

┌─────────────────────────────────────────────────────────────┐ │ Application Layer (Your Code) │ ├─────────────────────────────────────────────────────────────┤ │ vision High-Level API │ │ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────┐ ┌───────┐ │ │ │ YOLO26 │ │ YOLOv11 │ │ SAM2 │ │ SAM3 │ │RF-DETR│ │ │ │det/seg/ │ │det/seg/ │ │ Segment │ │Segment│ │det/seg│ │ │ │pose/obb/ │ │pose/obb/ │ │ │ │ │ │ │ │ │ │cls │ │cls │ │ │ │ │ │ │ │ │ └────┬─────┘ └────┬─────┘ └────┬─────┘ └──┬───┘ └──┬────┘ │ │ ┌────┴─────┐ ┌────┴─────┐ │ │ │ LTDETR │ │EdgeCrafter│ │ │ │ det │ │det/seg/ │ │ │ │ │ │pose │ │ │ └────┬─────┘ └────┬─────┘ │ │ └─────────────┴────────────┴──────────┴─────────┘ │ │ │ │ │ OnnxConfig.New() │ │ (Global Engine Singleton) │ ├─────────────────────────────────────────────────────────────┤ │ ort Low-Level Bindings │ │ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ │ │ Engine │ │ Session │ │ Value │ │ ortlog │ │ │ │(API reg) │ │(Inference)│ │(Tensors) │ │ (Logger) │ │ │ └────┬─────┘ └──────────┘ └──────────┘ └──────────┘ │ │ │ purego (Zero-CGO) │ │ ▼ │ ├─────────────────────────────────────────────────────────────┤ │ ONNX Runtime Shared Library (DLL/SO/DYLIB) │ └─────────────────────────────────────────────────────────────┘

Design Philosophy

  • ort layer: Complete Go bindings for the ONNX Runtime C API, responsible for dynamic library loading, API registration, Session management, and Tensor creation and data access. Developers can use the ort layer directly for low-level operations.
  • vision layer: Provides high-level wrappers for computer vision models on top of the ort layer. Each model has its own sub-package containing the complete preprocessing, inference, and postprocessing pipeline — ready to use out of the box.
  • Global Engine Singleton: The vision layer initializes a global Engine singleton via OnnxConfig.New(), loading the DLL only once per process. All models share the same Engine instance.

ort Low-Level Bindings

The ort package provides Go bindings for the ONNX Runtime C API, using purego for zero CGO calls.

Engine — Inference Engine

Engine is the core ONNX Runtime context, responsible for loading the dynamic library, registering APIs, and creating the environment.

import "github.com/DavidSche/raven-onnxruntime/ort"

engine, err := ort.NewEngine("./lib/onnxruntime.dll",
    ort.WithApiVersion(ort.ApiVersion26))
if err != nil { panic(err) }
defer engine.Destroy()

version := engine.GetVersion()
providers, _ := engine.AvailableProviders()

API Version Negotiation

When creating an Engine, the API version is determined by the following priority:

  1. The version specified via WithApiVersion() in code
  2. The value of the ORT_API_VERSION environment variable
  3. The default value DefaultApiVersion (currently 26)

If the requested version is unavailable, it automatically downgrades to the highest compatible version supported by the library.

Session — Inference Session

Session wraps an ONNX model inference session, supporting dynamic input/output name retrieval.

opts, err := engine.NewSessionOptions()
if err != nil { panic(err) }
defer opts.Destroy()

opts.SetIntraOpNumThreads(4)
opts.SetInterOpNumThreads(1)
opts.SetExecutionMode(ort.ExecutionModeSequential)
opts.SetMemPattern(true)
opts.SetGraphOptimizationLevel(ort.GraphOptimizationLevelAll)
opts.SetCpuMemArena(true)
opts.EnableCUDA()

session, err := engine.NewSession("model.onnx", opts)
if err != nil { panic(err) }
defer session.Destroy()

fmt.Println("Inputs:", session.InputNames)
fmt.Println("Outputs:", session.OutputNames)
shape, _ := session.GetInputShape(0)

Session.Run() — Execute Inference

inputData := make([]float32, 1*3*640*640)
inputTensor, err := engine.NewTensor([]int64{1, 3, 640, 640}, inputData)
if err != nil { panic(err) }
defer inputTensor.Destroy()

inputName := session.InputNames[0]
outputs, err := session.Run(map[string]*ort.Value{inputName: inputTensor})
if err != nil { panic(err) }

outputName := session.OutputNames[0]
outputValue := outputs[outputName]
data, _ := ort.GetTensorData[float32](outputValue)
shape, _ := outputValue.GetShape()
defer outputValue.Destroy()
Performance Optimization

Session.Run() internally implements zero-allocation optimization for output names (outputNameSlices / outputNamePtrs are allocated once during initMetadata), and input names are cached via sync.Map, so each Run no longer reallocates byte slices.

Value — Tensor Operations

Creating Tensors

tensor, err := engine.NewTensor([]int64{1, 3, 640, 640}, inputData)
// Supported types: []float32, []float64, []int64, []int32, []int16, []int8,
//                  []uint64, []uint32, []uint16, []uint8, []bool

Reading Tensor Data

data, err := ort.GetTensorData[float32](value)
shape, err := value.GetShape()
count, err := value.GetElementCount()
Important

All Value instances must have Destroy() called after use to release underlying resources, otherwise memory leaks will occur. It is recommended to use the defer value.Destroy() pattern.

vision High-Level API

The vision package provides ready-to-use wrappers for computer vision models on top of the ort layer. The core component is OnnxConfig, which initializes the global Engine singleton and Session options.

OnnxConfig

type OnnxConfig struct {
    SessionOptions     *ort.SessionOptions
    OnnxEngine         *ort.Engine
    OnnxRuntimeLibPath string  // Required: ONNX Runtime shared library path
    UseCuda            bool    // Optional: whether to enable CUDA
    NumThreads         int     // Optional: ONNX thread count
    ApiVersion         ort.ApiVersion // Optional: API version
    EnableCpuMemArena  bool    // Optional: whether to enable ONNX memory pool
}

Initialization Flow

Create OnnxConfig→ Set OnnxRuntimeLibPath→ Call New()→ Get OnnxEngine & SessionOptions→ Create Model Session 
oc := new(vision.OnnxConfig)
oc.OnnxRuntimeLibPath = "./lib/onnxruntime.dll"
oc.UseCuda = true

if err := oc.New(); err != nil { panic(err) }
defer oc.Destroy()

session, err := oc.OnnxEngine.NewSession("model.onnx", oc.SessionOptions)
Singleton Mechanism

OnnxConfig.New() uses sync.Mutex + state checking to implement the global Engine singleton. Unlike sync.Once, DLL load failures can be retried. Only one DLL path is allowed per process.

YOLO26

YOLO26 is the latest generation of object detection models from Ultralytics. This project supports all five of its tasks. Package path: github.com/DavidSche/raven-onnxruntime/vision/yolo26

Config

type Config struct {
    ModelPath          string
    OnnxRuntimeLibPath string
    ConfThreshold      float32       // Confidence threshold (default 0.45)
    IOUThreshold       float32       // NMS IOU threshold (default 0.45)
    MaskThreshold      float32       // Mask binarization threshold (default 0.5)
    InputSize          int           // Input size (default 640)

Object Detection (DetEngine)

Detection output format: [N, 300, 6], each row [x1, y1, x2, y2, score, class_id].

cfg := yolo26.DefaultDetConfig()
cfg.ModelPath = "models/yolo26m.onnx"
cfg.OnnxRuntimeLibPath = "./lib/onnxruntime.dll"
cfg.UseCuda = true

engine, err := yolo26.NewDetEngine(cfg)
if err != nil { panic(err) }
defer engine.Destroy()

img, _ := imageutil.Open("test.jpg")

// Single image inference
results, err := engine.Predict(img)

// Batch inference
batchResults, err := engine.PredictBatch([]image.Image{img1, img2, img3})

for _, res := range results {
    fmt.Printf("ClassID: %d, Score: %.2f, Box: %v\n",
        res.ClassID, res.Score, res.Box)
}

type DetResult struct {
    ClassID int
    Score   float32
    Box     image.Rectangle
}

YOLOv11 vs YOLO26

YOLOv11 has a default IOU threshold of 0.5 (YOLO26 uses 0.45), while the rest of the API is identical. YOLOv11 post-processing uses the traditional NMS pipeline (including anchor decoding), whereas YOLO26 detection model outputs are already NMS-postprocessed results.

SAM2

SAM2 (Segment Anything Model 2) is Meta's image segmentation model using an encoder-decoder architecture. Package path: github.com/DavidSche/raven-onnxruntime/vision/sam2

Workflow

1. Create Engine→ 2. EncodeImage→ 3. Decode (pass points/boxes)→ 4. Get Mask 
config := sam2.Config{
    OnnxRuntimeLibPath: "./lib/onnxruntime.dll",
    EncodeModelPath:    "models/sam2/vision_encoder.onnx",
    DecodeModelPath:    "models/sam2/prompt_encoder_mask_decoder.onnx",
}

engine, err := sam2.NewEngine(config)
if err != nil { panic(err) }
defer engine.Destroy()

img, _ := imageutil.Open("person.jpg")
imgCtx, err := engine.EncodeImage(img)
if err != nil { panic(err) }
defer imgCtx.Destroy()

points := []sam2.Point{
    {X: 367, Y: 168, Label: sam2.LabelBoxTopLeft},
    {X: 441, Y: 349, Label: sam2.LabelBoxBotRight},
}
maskImg, score, err := imgCtx.Decode(points)

// Or get raw data
result, err := imgCtx.DecodeRaw(points)
// result.Mask: []uint8 (0 or 255)
// result.Score: float32
// result.Width, result.Height: int

Point Label Types

LabelValueDescription
LabelBackground0Background / exclusion point
LabelForeground1Foreground / click point
LabelBoxTopLeft2Bounding box top-left corner
LabelBoxBotRight3Bounding box bottom-right corner
Performance Optimization

EncodeImage is the time-consuming operation (encoder inference), while Decode is fast. For multiple different prompts on the same image, encode once and then call Decode multiple times.

Batch Inference

Batch inference allows processing multiple images at once, fully utilizing GPU parallelism and significantly improving throughput.

Supported Models

ModelTaskBatch MethodNotes
YOLO26Detection / PosePredictBatchNative support, single Run
RF-DETRDetection / SegmentationPredictBatchRequires DynamicBatch=true
YOLO26Segmentation / OBB / Classification—Single-frame Predict only
YOLOv11All—Single-frame Predict only
SAM2 / SAM3Segmentation—Encoder-decoder architecture, not suitable for batching

Usage Example

engine, _ := yolo26.NewDetEngine(cfg)
defer engine.Destroy()

imgs := []image.Image{img1, img2, img3, img4}
batchResults, err := engine.PredictBatch(imgs)
// batchResults[0] = detection results for img1
// batchResults[1] = detection results for img2

// RF-DETR batch inference
cfg.DynamicBatch = true
rfdetrEngine, _ := rfdetr.NewDetEngine(cfg)
batchResults, err := rfdetrEngine.PredictBatch(imgs)
Internal Implementation

PredictBatch internally creates an [N, 3, H, W] input tensor, completes inference in a single Session.Run(), then splits results by batch dimension for separate post-processing. Predict() delegates to PredictBatch([]image.Image{img}) internally, so there is no overhead for single-frame scenarios.

Model Pipeline

You can combine detection and segmentation models to implement a "detect then segment" pipeline. Typical scenario: YOLO detects objects → SAM performs precise segmentation.

yoloCfg := yolo26.DefaultDetConfig()
yoloCfg.ModelPath = "models/yolo26m.onnx"
yoloCfg.OnnxRuntimeLibPath = "./lib/onnxruntime.dll"

yoloEngine, err := yolo26.NewDetEngine(yoloCfg)
if err != nil { panic(err) }
defer yoloEngine.Destroy()

img, _ := imageutil.Open("person.jpg")
yoloResults, err := yoloEngine.Predict(img)

var targetBox image.Rectangle
for _, res := range yoloResults {
    if res.ClassID == 0 { // COCO: person
        targetBox = res.Box
        break
    }
}

samCfg := sam3.Config{
    OnnxRuntimeLibPath: "./lib/onnxruntime.dll",
    VisionModelPath:    "models/sam3_vision_encoder.onnx",
    TextModelPath:      "models/sam3_text_encoder.onnx",
    DecoderModelPath:   "models/sam3_decoder.onnx",
}

samEngine, err := sam3.NewEngine(samCfg)
if err != nil { panic(err) }
defer samEngine.Destroy()

imgCtx, err := samEngine.EncodeImage(img)
if err != nil { panic(err) }
defer imgCtx.Destroy()

points := []sam3.Point{
    {X: float32(targetBox.Min.X), Y: float32(targetBox.Min.Y), Label: sam3.LabelPosBox},
    {X: float32(targetBox.Max.X), Y: float32(targetBox.Max.Y), Label: sam3.LabelPosBox},
}
maskImg, score, err := imgCtx.Decode(points)
Pipeline Advantages

The YOLO + SAM combination balances detection speed and segmentation accuracy. YOLO quickly locates target regions, while SAM generates pixel-level precise masks within those regions. This pattern is particularly suitable for automated scenarios requiring high-precision segmentation.

CUDA Acceleration

Enabling CUDA can significantly improve inference speed, especially for large models and batch inference scenarios.

Prerequisites

  • NVIDIA GPU (compute capability 6.0+)
  • CUDA Toolkit installed
  • ONNX Runtime GPU version shared library

How to Enable

// Method 1: Enable via Config (recommended)
cfg := yolo26.DefaultDetConfig()
cfg.UseCuda = true

// Method 2: Enable via ort layer
opts, _ := engine.NewSessionOptions()
opts.EnableCUDA()
Error Handling

If CUDA is requested but ONNX Runtime does not detect CUDAExecutionProvider, OnnxConfig.New() will return a clear error message instead of silently falling back to CPU. This ensures that GPU inference is not accidentally replaced by CPU inference in scenarios where GPU is required.

providers, _ := engine.AvailableProviders()
// Example output: ["CPUExecutionProvider", "CUDAExecutionProvider"]

CpuMemArena Explanation

EnableCpuMemArena = false (default)

Disables the memory pool — inference is slightly slower, but memory is immediately returned to the OS after Destroy. Suitable for short-lifecycle scenarios.

EnableCpuMemArena = true

Enables the memory pool — inference is fastest, but memory is cached for reuse after Destroy. Suitable for long-running services.

API Version Negotiation

raven-onnxruntime defaults to ONNX Runtime C API version 26 and supports automatic downgrade for compatibility with different versions of the shared library.

Version Negotiation Strategy

Code WithApiVersion(23) Env ORT_API_VERSION=20 Default DefaultApiVersion(26) ↓ ↓ ↓ └─────────── resolveApiVersion() priority ─────────────┘ Code parameter > Environment variable > Default value ↓ getApi(requestedVersion) ↓ ┌─── Success → Use requested version └─── Failure → Auto-downgrade: find the highest available version < requestedVersion from supportedApiVersions ↓ ┌── Found → Use downgraded version, output Warn log └── Not found → Return error

FAQ

Q: How do I get the ONNX Runtime shared library?

Download the pre-built package for your platform from ONNX Runtime Releases:

  • Windows: onnxruntime-win-x64-1.x.x.zip (CPU) or onnxruntime-win-x64-gpu-1.x.x.zip (GPU)
  • Linux: onnxruntime-linux-x64-1.x.x.tgz
  • macOS: onnxruntime-osx-arm64-1.x.x.tgz

Q: Why does CUDA enablement fail?

Please verify:

  1. You are using the GPU version of the ONNX Runtime shared library
  2. CUDA Toolkit and cuDNN are correctly installed
  3. Confirm CUDAExecutionProvider is in the list via engine.AvailableProviders()

Q: Can multiple models share the same Engine?

Yes. The vision layer's global Engine singleton ensures all models share the same ONNX Runtime environment. Each model creates its own independent Session, but they share the same Engine instance and DLL underneath.

Q: How do I choose between YOLO26 and YOLOv11?

YOLO26 is the latest generation model with higher accuracy, and its detection output is already NMS-postprocessed (faster inference). YOLOv11 is the previous generation model with post-processing that includes the traditional NMS pipeline. YOLO26 is recommended as the primary choice.

Q: What is the difference between Predict and PredictBatch?

Predict processes a single image, while PredictBatch processes multiple images at once. For models that support batching, Predict delegates to PredictBatch internally, so there is no overhead for single-frame scenarios. Batch inference can significantly improve throughput on GPU.

Q: How do I handle memory leaks?

Ensure all Value instances created via NewTensor / Session.Run have Destroy() called. It is recommended to use the defer value.Destroy() pattern. Session and Engine also need Destroy() called when no longer in use.

Q: Which platforms are supported?

Windows, Linux, and macOS are supported. Dynamic library loading is adapted for different platforms via the internal/sys package:

  • Windows: Uses LoadLibrary to load .dll
  • Linux/macOS: Uses dlopen to load .so / .dylib

Q: How do I customize model post-processing?

You can use the ort low-level API directly:

  1. Create a Session via Engine.NewSession()
  2. Create input Tensors via Engine.NewTensor()
  3. Execute inference via Session.Run()
  4. Read output data via ort.GetTensorData[T]()
  5. Implement your own post-processing logic
