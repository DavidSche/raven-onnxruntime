raven-onnxruntime 使用手册

基于 purego 的 Zero-CGO ONNX Runtime Go 推理框架，提供 YOLO26 / YOLOv11 / SAM2 / SAM3 / RF-DETR 等模型的即用型封装

Go 1.24+Zero-CGOCUDA 支持批量推理

项目概述

raven-onnxruntime 是一个 Go 语言推理库，基于 ONNX Runtime，使用 purego 实现 Zero-CGO 调用 ONNX Runtime 共享库，提供 YOLO 模型系列和 SAM2/SAM3 的即用型封装。

本项目是 go-vision 和 onnxruntime_purego 的合并版本，并在性能和稳定性上进行了大量改进。

快速上手

环境要求

  • Go 1.24+
  • ONNX Runtime 共享库（onnxruntime.dll / libonnxruntime.so / libonnxruntime.dylib）
  • （可选）NVIDIA GPU + CUDA 以启用 GPU 加速

安装

go get github.com/DavidSche/raven-onnxruntime

最小示例：YOLO26 目标检测

package main

import (
    "fmt"
    "github.com/DavidSche/raven-onnxruntime/vision/yolo26"
    "github.com/up-zero/gotool/imageutil"
)

func main() {
    cfg := yolo26.DefaultDetConfig()
    cfg.ModelPath = "models/yolo26/yolo26m.onnx"
    cfg.OnnxRuntimeLibPath = "./lib/onnxruntime.dll"
    cfg.UseCuda = true

    engine, err := yolo26.NewDetEngine(cfg)
    if err != nil { panic(err) }
    defer engine.Destroy()

    img, _ := imageutil.Open("test.jpg")
    results, err := engine.Predict(img)
    if err != nil { panic(err) }

    for _, res := range results {
        fmt.Printf("ClassID: %d, Score: %.2f, Box: %v\n",
            res.ClassID, res.Score, res.Box)
    }
}
提示

所有引擎都遵循相同的模式：创建配置 → 创建引擎 → 调用 Predict → 处理结果 → Destroy 释放资源。只需替换引擎类型和配置即可切换不同模型。

整体架构

raven-onnxruntime 采用两层架构设计：

设计理念

  • ort 层：对 ONNX Runtime C API 的完整 Go 绑定，负责动态库加载、API 注册、Session 管理、Tensor 创建与数据访问。开发者可直接使用 ort 层进行底层操作。
  • vision 层：在 ort 层之上提供计算机视觉模型的高级封装，每个模型一个子包，包含预处理、推理、后处理的完整流程，开箱即用。
  • 全局 Engine 单例：vision 层通过 OnnxConfig.New() 初始化全局 Engine 单例，整个进程只加载一次 DLL，所有模型共享同一 Engine 实例。

RMP 模型包规范

RMP (Raven Model Package) 是 raven-onnxruntime 定义的模型包规范，将 ONNX 子模型、元数据和辅助文件组织为自描述的目录结构。

设计动机

多子模型架构（如 Grounded-SAM-2 有 5 个 ONNX、SAM3 有 3 个 ONNX）如果由调用方逐个指定子模型路径，会导致配置膨胀且违反职责边界。RMP 规范让模型包自描述，调用方只需指定目录路径即可。

目录结构

grounded-sam2/                 # 模型包根目录
├── manifest.json              # RMP 清单文件 (必须)
├── grounded_sam2_gdino_image_encoder.onnx
├── grounded_sam2_gdino_text_encoder.onnx
├── grounded_sam2_gdino_detector.onnx
├── grounded_sam2_sam2_image_encoder.onnx
├── grounded_sam2_sam2_mask_decoder.onnx
└── labels.txt                 # (可选) 标签文件

manifest.json 格式

{
  "format_version": "1.0",
  "model_type": "grounded-sam2",
  "model_version": "1.0.0",
  "task": "segmentation",
  "runtime": "onnxruntime",
  "input_size": [800, 800],
  "labels": null,
  "sub_models": {
    "gdino_image_encoder": "grounded_sam2_gdino_image_encoder.onnx",
    "gdino_text_encoder": "grounded_sam2_gdino_text_encoder.onnx",
    "gdino_detector": "grounded_sam2_gdino_detector.onnx",
    "sam2_image_encoder": "grounded_sam2_sam2_image_encoder.onnx",
    "sam2_mask_decoder": "grounded_sam2_sam2_mask_decoder.onnx"
  },
  "params": {
    "gdino": { "hidden_dim": 256, "num_queries": 900 },
    "sam2": { "image_size": 1024, "hidden_dim": 256 }
  }
}

字段说明

字段类型必须说明
format_versionstring是manifest 格式版本，当前为 "1.0"
model_typestring是模型类型标识，如 "grounded-sam2"、"sam3"、"yolo26"
model_versionstring否模型版本号，如 "2.1.0"
taskstring否任务类型："detect"、"segmentation"、"classify"、"embedding"
runtimestring否运行时类型，当前为 "onnxruntime"
input_size[int, int]否模型输入尺寸 [H, W]
labelsstring|null否标签文件相对路径，如 "labels.txt"
sub_modelsobject是子模型名称 → ONNX 文件相对路径的映射
paramsobject否模型结构参数，供引擎自动配置

使用方式

多子模型引擎（SAM2、SAM3、GroundingDINO、Grounded-SAM-2）的 Config 只需设置 ModelPath 指向模型包目录，引擎内部自动从 manifest.json 解析子模型路径：

// SAM3 示例 — 只需指定目录
cfg := sam3.DefaultConfig()
cfg.ModelPath = "./models/sam3"       // 目录内包含 manifest.json
cfg.OnnxRuntimeLibPath = "./lib/onnxruntime.dll"
cfg.UseCuda = true

engine, err := sam3.NewEngine(cfg)    // 自动从 manifest.json 发现子模型
回退机制

如果目录中没有 manifest.json，引擎会回退到默认文件名（如 sam3_image_encoder.onnx），确保向后兼容。

单模型 vs 多模型

模型类型子模型数Config 字段需要 manifest
YOLO26 / YOLOv111ModelPath → .onnx 文件否（可选）
RF-DETR / LTDETR1ModelPath → .onnx 文件否（可选）
SAM22ModelPath → 目录推荐
SAM33ModelPath → 目录推荐
GroundingDINO3ModelPath → 目录推荐
Grounded-SAM-25ModelPath → 目录必须

导出器生成

各模型的 export_onnx.py 导出脚本会自动生成 manifest.json，无需手动创建：

python export_onnx.py
# 输出完整的模型包目录：
# grounded-sam2/
# ├── manifest.json
# ├── *.onnx
# └── ...

ort 底层绑定

ort 包是 ONNX Runtime C API 的 Go 绑定层，使用 purego 实现零 CGO 调用。

Engine — 推理引擎

Engine 是 ONNX Runtime 的核心上下文，负责加载动态库、注册 API、创建环境。

import "github.com/DavidSche/raven-onnxruntime/ort"

engine, err := ort.NewEngine("./lib/onnxruntime.dll",
    ort.WithApiVersion(ort.ApiVersion26))
if err != nil { panic(err) }
defer engine.Destroy()

version := engine.GetVersion()
providers, _ := engine.AvailableProviders()

API 版本协商

创建 Engine 时，按以下优先级确定 API 版本：

  1. 代码中通过 WithApiVersion() 指定的版本
  2. 环境变量 ORT_API_VERSION 的值
  3. 默认值 DefaultApiVersion（当前为 26）

如果请求的版本不可用，会自动降级到库支持的最高兼容版本。

Session — 推理会话

Session 封装了 ONNX 模型的推理会话，支持动态获取输入/输出名称。

opts, err := engine.NewSessionOptions()
if err != nil { panic(err) }
defer opts.Destroy()

opts.SetIntraOpNumThreads(4)
opts.SetInterOpNumThreads(1)
opts.SetExecutionMode(ort.ExecutionModeSequential)
opts.SetMemPattern(true)
opts.SetGraphOptimizationLevel(ort.GraphOptimizationLevelAll)
opts.SetCpuMemArena(true)
opts.EnableCUDA()

session, err := engine.NewSession("model.onnx", opts)
if err != nil { panic(err) }
defer session.Destroy()

fmt.Println("Inputs:", session.InputNames)
fmt.Println("Outputs:", session.OutputNames)
shape, _ := session.GetInputShape(0)

Session.Run() — 执行推理

inputData := make([]float32, 1*3*640*640)
inputTensor, err := engine.NewTensor([]int64{1, 3, 640, 640}, inputData)
if err != nil { panic(err) }
defer inputTensor.Destroy()

inputName := session.InputNames[0]
outputs, err := session.Run(map[string]*ort.Value{inputName: inputTensor})
if err != nil { panic(err) }

outputName := session.OutputNames[0]
outputValue := outputs[outputName]
data, _ := ort.GetTensorData[float32](outputValue)
shape, _ := outputValue.GetShape()
defer outputValue.Destroy()
性能优化

Session.Run() 内部对输出名称做了零分配优化（outputNameSlices / outputNamePtrs 在 initMetadata 时一次性分配），输入名称通过 sync.Map 缓存，每次 Run 不再重新分配字节切片。

Value — 张量操作

创建 Tensor

tensor, err := engine.NewTensor([]int64{1, 3, 640, 640}, inputData)
// 支持: []float32, []float64, []int64, []int32, []int16, []int8,
//       []uint64, []uint32, []uint16, []uint8, []bool

读取 Tensor 数据

data, err := ort.GetTensorData[float32](value)
shape, err := value.GetShape()
count, err := value.GetElementCount()
注意

所有 Value 在使用完毕后必须调用 Destroy() 释放底层资源，否则会造成内存泄漏。建议使用 defer value.Destroy() 模式。

vision 高层封装

vision 包在 ort 层之上提供计算机视觉模型的即用型封装。核心是 OnnxConfig，负责初始化全局 Engine 单例和 Session 选项。

OnnxConfig

type OnnxConfig struct {
    SessionOptions     *ort.SessionOptions
    OnnxEngine         *ort.Engine
    OnnxRuntimeLibPath string  // 必填：ONNX Runtime 动态库路径
    UseCuda            bool    // 可选：是否启用 CUDA
    NumThreads         int     // 可选：ONNX 线程数
    ApiVersion         ort.ApiVersion // 可选：API 版本
    EnableCpuMemArena  bool    // 可选：是否启用 ONNX 内存池
}

初始化流程

创建 OnnxConfig→ 设置 OnnxRuntimeLibPath→ 调用 New()→ 获取 OnnxEngine & SessionOptions→ 创建模型 Session 
oc := new(vision.OnnxConfig)
oc.OnnxRuntimeLibPath = "./lib/onnxruntime.dll"
oc.UseCuda = true

if err := oc.New(); err != nil { panic(err) }
defer oc.Destroy()

session, err := oc.OnnxEngine.NewSession("model.onnx", oc.SessionOptions)
单例机制

OnnxConfig.New() 使用 sync.Mutex + 状态检查实现全局 Engine 单例。与 sync.Once 不同，DLL 加载失败后可以重试。同一进程只允许加载一个 DLL 路径。

Session 选项默认配置

选项值说明
IntraOpNumThreads用户指定 / CPU 核心数算子内并行线程数
InterOpNumThreads1算子间并行线程数
ExecutionModeSequential顺序执行模式
MemPatternEnabled内存模式优化
GraphOptimizationLevelORT_ENABLE_ALL图优化级别：全部启用
CpuMemArena用户指定CPU 内存池策略

YOLO26

YOLO26 是 Ultralytics 最新一代目标检测模型，本项目支持其全部五种任务。包路径：github.com/DavidSche/raven-onnxruntime/vision/yolo26

Config 配置

type Config struct {
    ModelPath          string
    OnnxRuntimeLibPath string
    ConfThreshold      float32       // 置信度阈值（默认 0.45）
    IOUThreshold       float32       // NMS IOU 阈值（默认 0.45）
    MaskThreshold      float32       // Mask 二值化阈值（默认 0.5）
    InputSize          int           // 输入尺寸（默认 640）
    NumClasses         int           // 类别数（默认 80）
    NumMaskCoeffs      int           // Mask 系数数（默认 32）
    NumKeyPoints       int           // 关键点数（默认 17）
    UseCuda            bool
    NumThreads         int
    EnableCpuMemArena  bool
    ApiVersion         ort.ApiVersion
}

目标检测 (DetEngine)

检测输出格式：[N, 300, 6]，每行 [x1, y1, x2, y2, score, class_id]。

cfg := yolo26.DefaultDetConfig()
cfg.ModelPath = "models/yolo26/yolo26m.onnx"
cfg.OnnxRuntimeLibPath = "./lib/onnxruntime.dll"
cfg.UseCuda = true

engine, err := yolo26.NewDetEngine(cfg)
if err != nil { panic(err) }
defer engine.Destroy()

img, _ := imageutil.Open("test.jpg")

// 单帧推理
results, err := engine.Predict(img)

// 批量推理
batchResults, err := engine.PredictBatch([]image.Image{img1, img2, img3})

for _, res := range results {
    fmt.Printf("ClassID: %d, Score: %.2f, Box: %v\n",
        res.ClassID, res.Score, res.Box)
}

type DetResult struct {
    ClassID int
    Score   float32
    Box     image.Rectangle
}

实例分割 (SegEngine)

分割模型有两个输出：[1, 300, 38]（检测+Mask系数）和 [1, 32, 160, 160]（Mask原型）。

cfg := yolo26.DefaultSegConfig()
cfg.ModelPath = "models/yolo26/yolo26m-seg.onnx"
cfg.OnnxRuntimeLibPath = "./lib/onnxruntime.dll"

engine, err := yolo26.NewSegEngine(cfg)
if err != nil { panic(err) }
defer engine.Destroy()

img, _ := imageutil.Open("test.jpg")
results, err := engine.Predict(img)

for idx, res := range results {
    fmt.Printf("ClassID: %d, Score: %.2f, Box: %v\n",
        res.ClassID, res.Score, res.Box)
    imageutil.Save(fmt.Sprintf("mask_%d.png", idx), res.Mask, 100)
}

type SegResult struct {
    ClassID int
    Score   float32
    Box     image.Rectangle
    Mask    *image.Gray
}

姿态估计 (PoseEngine)

姿态模型输出格式：[N, 300, 57]（6 基础属性 + 17×3 关键点），支持批量推理和通道优先格式自动检测。

cfg := yolo26.DefaultPoseConfig()
cfg.ModelPath = "models/yolo26/yolo26m-pose.onnx"
cfg.OnnxRuntimeLibPath = "./lib/onnxruntime.dll"
cfg.NumKeyPoints = 17

engine, err := yolo26.NewPoseEngine(cfg)
if err != nil { panic(err) }
defer engine.Destroy()

img, _ := imageutil.Open("person.jpg")
results, err := engine.Predict(img)

// 绘制骨架
dst := yolo26.DrawPoseResult(img, results)
imageutil.Save("pose_output.jpg", dst, 50)

type PoseResult struct {
    ClassID   int
    Score     float32
    Box       image.Rectangle
    KeyPoints []KeyPoint
}

type KeyPoint struct {
    X, Y  int
    Score float32
}

旋转目标检测 (OBBEngine)

旋转检测输出格式：[1, 300, 7]，每行 [cx, cy, w, h, score, class_id, angle]。

cfg := yolo26.DefaultOBBConfig()
cfg.ModelPath = "models/yolo26/yolo26m-obb.onnx"

engine, err := yolo26.NewOBBEngine(cfg)

img, _ := imageutil.Open("ship.jpg")

for _, res := range results {

type OBBResult struct {
    ClassID int
    Score   float32
    Corners [4]image.Point

分类模型输入尺寸为 224×224，输出 [1, 1000] 的 logits。

YOLOv11

YOLOv11 的 API 与 YOLO26 完全一致，仅包路径和默认配置不同。包路径：github.com/DavidSche/raven-onnxruntime/vision/yolov11

任务引擎默认配置函数结果类型
目标检测DetEngineDefaultDetConfig()DetResult
实例分割SegEngineDefaultSegConfig()SegResult
姿态估计PoseEngineDefaultPoseConfig()PoseResult
旋转检测OBBEngineDefaultOBBConfig()OBBResult
图像分类ClsEngineDefaultClsConfig()ClassResult
import "github.com/DavidSche/raven-onnxruntime/vision/yolov11"

cfg := yolov11.DefaultDetConfig()
cfg.ModelPath = "models/yolo11/yolo11m.onnx"
cfg.OnnxRuntimeLibPath = "./lib/onnxruntime.dll"

engine, err := yolov11.NewDetEngine(cfg)

results, err := engine.Predict(img)
YOLOv11 与 YOLO26 的区别

YOLOv11 的 IOU 阈值默认为 0.5（YOLO26 为 0.45），其余 API 完全一致。YOLOv11 的后处理使用传统 NMS 流程（含 anchor 解码），YOLO26 的检测模型输出已是 NMS 后的结果。

SAM2

SAM2（Segment Anything Model 2）是 Meta 的图像分割模型，采用编码器-解码器架构。包路径：github.com/DavidSche/raven-onnxruntime/vision/sam2

工作流程

1. 创建 Engine→ 2. EncodeImage→ 3. Decode (传入点/框)→ 4. 获取 Mask 
config := sam2.Config{
    OnnxRuntimeLibPath: "./lib/onnxruntime.dll",
    ModelPath:          "models/sam2",  // 目录内包含 manifest.json + ONNX 子模型
}

engine, err := sam2.NewEngine(config)
if err != nil { panic(err) }
defer engine.Destroy()

img, _ := imageutil.Open("person.jpg")
imgCtx, err := engine.EncodeImage(img)
if err != nil { panic(err) }
defer imgCtx.Destroy()

points := []sam2.Point{
    {X: 367, Y: 168, Label: sam2.LabelBoxTopLeft},
    {X: 441, Y: 349, Label: sam2.LabelBoxBotRight},
}
maskImg, score, err := imgCtx.Decode(points)

// 或获取原始数据
result, err := imgCtx.DecodeRaw(points)
// result.Mask: []uint8 (0 或 255)
// result.Score: float32
// result.Width, result.Height: int

性能优化

EncodeImage 是耗时操作（编码器推理），而 Decode 很快。对于同一张图片的多次不同提示，只需编码一次，然后多次调用 Decode。

批量推理

批量推理允许一次处理多张图片，充分利用 GPU 并行能力，显著提升吞吐量。

支持的模型

模型任务批量方法说明
YOLO26检测 / 姿态PredictBatch原生支持，单次 Run
RF-DETR检测 / 分割PredictBatch需要 DynamicBatch=true
YOLO26分割 / OBB / 分类—仅支持单帧 Predict
YOLOv11全部—仅支持单帧 Predict
SAM2 / SAM3分割—编码器-解码器架构，不适合批量
Depth-Anything-3深度估计—单帧单目深度估计

使用示例

engine, _ := yolo26.NewDetEngine(cfg)
defer engine.Destroy()

imgs := []image.Image{img1, img2, img3, img4}
batchResults, err := engine.PredictBatch(imgs)
// batchResults[0] = img1 的检测结果
// batchResults[1] = img2 的检测结果

// RF-DETR 批量推理
cfg.DynamicBatch = true
rfdetrEngine, _ := rfdetr.NewDetEngine(cfg)
batchResults, err := rfdetrEngine.PredictBatch(imgs)
内部实现

PredictBatch 内部创建 [N, 3, H, W] 的输入张量，一次 Session.Run() 完成推理，然后按 batch 维度拆分结果分别后处理。Predict() 内部委托给 PredictBatch([]image.Image{img})，单帧场景无额外开销。

模型流水线

可以将检测模型与分割模型组合，实现"先检测再分割"的流水线。典型场景：YOLO 检测目标 → SAM 精确分割。

yoloCfg := yolo26.DefaultDetConfig()
yoloCfg.ModelPath = "models/yolo26/yolo26m.onnx"
yoloCfg.OnnxRuntimeLibPath = "./lib/onnxruntime.dll"

yoloEngine, err := yolo26.NewDetEngine(yoloCfg)
if err != nil { panic(err) }
defer yoloEngine.Destroy()

img, _ := imageutil.Open("person.jpg")
yoloResults, err := yoloEngine.Predict(img)

var targetBox image.Rectangle
for _, res := range yoloResults {
    if res.ClassID == 0 { // COCO: person
        targetBox = res.Box
        break
    }
}

samCfg := sam3.Config{
    OnnxRuntimeLibPath: "./lib/onnxruntime.dll",
    ModelPath:          "models/sam3",  // 目录内包含 manifest.json + ONNX 子模型
}

samEngine, err := sam3.NewEngine(samCfg)
if err != nil { panic(err) }
defer samEngine.Destroy()

imgCtx, err := samEngine.EncodeImage(img)
if err != nil { panic(err) }
defer imgCtx.Destroy()

points := []sam3.Point{
    {X: float32(targetBox.Min.X), Y: float32(targetBox.Min.Y), Label: sam3.LabelPosBox},
    {X: float32(targetBox.Max.X), Y: float32(targetBox.Max.Y), Label: sam3.LabelPosBox},
}
maskImg, score, err := imgCtx.Decode(points)
流水线优势

YOLO + SAM 组合兼顾了检测的速度和分割的精度。YOLO 快速定位目标区域，SAM 在该区域内生成像素级精确的 Mask。这种模式特别适合需要高精度分割的自动化场景。

CUDA 加速

启用 CUDA 可以显著提升推理速度，特别是对于大模型和批量推理场景。

前提条件

  • NVIDIA GPU（计算能力 6.0+）
  • CUDA Toolkit 已安装
  • ONNX Runtime GPU 版本的共享库

启用方式

// 方式 1：通过 Config 启用（推荐）
cfg := yolo26.DefaultDetConfig()
cfg.UseCuda = true

// 方式 2：通过 ort 层启用
opts, _ := engine.NewSessionOptions()
opts.EnableCUDA()
错误处理

如果请求 CUDA 但 ONNX Runtime 未检测到 CUDAExecutionProvider，OnnxConfig.New() 会返回明确的错误信息，而不是静默降级到 CPU。这确保了在需要 GPU 的场景下不会意外使用 CPU 推理。

providers, _ := engine.AvailableProviders()
// 输出示例: ["CPUExecutionProvider", "CUDAExecutionProvider"]

CpuMemArena 说明

EnableCpuMemArena = false（默认）

禁用内存池，推理速度略慢，但 Destroy 后内存立即归还操作系统。适合短生命周期场景。

EnableCpuMemArena = true

启用内存池，推理速度最快，但 Destroy 后内存被缓存以供复用。适合长期运行的服务。

API 版本协商

raven-onnxruntime 默认使用 ONNX Runtime C API 版本 26，并支持自动降级以兼容不同版本的共享库。

版本协商策略

代码 WithApiVersion(23) 环境变量 ORT_API_VERSION=20 默认 DefaultApiVersion(26) ↓ ↓ ↓ └─────────── resolveApiVersion() 优先级 ──────────────┘ 代码参数 > 环境变量 > 默认值 ↓ getApi(requestedVersion) ↓ ┌─── 成功 → 使用请求的版本 └─── 失败 → 自动降级：从 supportedApiVersions 中 找到 < requestedVersion 的最高可用版本 ↓ ┌── 找到 → 使用降级版本，输出 Warn 日志 └── 未找到 → 返回错误

常见问题

Q: 是否需要安装 C 编译器？

不需要。本项目使用 purego 实现 Zero-CGO 调用，无需安装任何 C 编译器（如 GCC、MSVC）。只需确保 ONNX Runtime 共享库文件存在即可。

Q: 如何获取 ONNX Runtime 共享库？

从 ONNX Runtime Releases 下载对应平台的预编译包：

  • Windows: onnxruntime-win-x64-1.x.x.zip（CPU）或 onnxruntime-win-x64-gpu-1.x.x.zip（GPU）
  • Linux: onnxruntime-linux-x64-1.x.x.tgz
  • macOS: onnxruntime-osx-arm64-1.x.x.tgz

Q: 为什么 CUDA 启用失败？

请确认：

  1. 使用的是 GPU 版本的 ONNX Runtime 共享库
  2. CUDA Toolkit 和 cuDNN 已正确安装
  3. 通过 engine.AvailableProviders() 确认 CUDAExecutionProvider 在列表中

Q: 多个模型可以共享同一个 Engine 吗？

可以。vision 层的全局 Engine 单例确保所有模型共享同一个 ONNX Runtime 环境。每个模型会创建独立的 Session，但底层共享同一个 Engine 实例和 DLL。

Q: 如何选择 YOLO26 和 YOLOv11？

YOLO26 是最新一代模型，精度更高，且检测输出已经是 NMS 后的结果（推理更快）。YOLOv11 是上一代模型，后处理包含传统 NMS 流程。建议优先使用 YOLO26。

Q: Predict 和 PredictBatch 的区别？

Predict 处理单张图片，PredictBatch 一次处理多张图片。对于支持批量的模型，Predict 内部委托给 PredictBatch，单帧场景无额外开销。批量推理在 GPU 上可以显著提升吞吐量。

Q: 如何处理内存泄漏？

确保所有通过 NewTensor / Session.Run 创建的 Value 都调用了 Destroy()。建议使用 defer value.Destroy() 模式。Session 和 Engine 也需要在不再使用时调用 Destroy()。

Q: 支持哪些平台？

支持 Windows、Linux、macOS。动态库加载通过 internal/sys 包适配不同平台：

  • Windows: 使用 LoadLibrary 加载 .dll
  • Linux/macOS: 使用 dlopen 加载 .so / .dylib

Q: 如何自定义模型的后处理？

可以直接使用 ort 底层 API：

  1. 通过 Engine.NewSession() 创建 Session
  2. 通过 Engine.NewTensor() 创建输入 Tensor
  3. 通过 Session.Run() 执行推理
  4. 通过 ort.GetTensorData[T]() 读取输出数据
  5. 自行实现后处理逻辑
